Claude Skills · SKILL.md 만들기

설명서 한 장으로
Claude에게 내 일하는 법을 알려주세요

Claude의 스킬은 SKILL.md라는 글 파일 하나에서 시작합니다. 맨 위에 이름과 “언제 쓰는지”를 적고, 아래에 일하는 순서와 기준을 적으면 됩니다. 코딩을 몰라도 만들 수 있습니다.

무엇을 만드나

스킬은 폴더 하나,
그 안의 SKILL.md가 주인공입니다

스킬 폴더를 만들고 그 안에 SKILL.md를 넣으면 가장 작은 스킬이 완성됩니다. 참고자료, 서식, 스크립트는 필요할 때만 옆에 더 둡니다. 폴더 이름은 스킬 이름과 같게 짓는 것이 좋습니다.

파일 이름을 정확히: 반드시 대문자 SKILL.md입니다. skill.md나 Skill.md로 저장하면 Claude가 스킬로 알아보지 못할 수 있습니다.
SKILL.md 들여다보기

위에는 이름표,
아래에는 일하는 방법

SKILL.md는 두 부분으로 나뉩니다. --- 두 줄 사이의 머리말(frontmatter)은 Claude가 항상 보는 이름표입니다. 그 아래 본문은 이 스킬이 골라졌을 때만 펼쳐 읽는 설명서입니다.

  1. 1
    머리말 · 이름표

    name과 description 두 줄이 핵심입니다. Claude는 이 설명을 보고 “지금 이 스킬을 꺼낼까?”를 판단합니다.

    항상 읽음 · 아주 짧게
  2. 2
    본문 · 업무 설명서

    평범한 마크다운으로 순서, 기준, 예시, 확인 방법을 적습니다. 500줄 안쪽으로 짧게 유지합니다.

    스킬이 골라질 때 읽음
  3. 3
    링크한 파일 · 참고 서랍

    길고 자세한 내용은 따로 두고 본문에서 경로만 알려 줍니다. 필요한 순간에만 열어 봅니다.

    필요할 때만 읽음
항목지켜야 할 규칙작성 요령
name 필수 영어 소문자, 숫자, 하이픈(-)만 쓰고 최대 64자입니다. “anthropic”, “claude”라는 단어는 넣을 수 없습니다. 하는 일이 보이게 짓습니다. pdf-processing, eli5-guide는 좋고 helper, tools는 너무 막연합니다.
description 필수 비워 둘 수 없고 최대 1,024자입니다. XML 태그는 쓸 수 없습니다. 무엇을 하는지 + 언제 쓰는지를 함께 적습니다. “나는 ~할 수 있어요”가 아니라 “~한다”처럼 3인칭으로 씁니다.
본문 형식 제한은 없지만 500줄 이하를 권장합니다. 길어지면 references/ 파일로 나누고, 본문에서 한 단계로 바로 연결합니다.

Claude Code에서는 disable-model-invocation, allowed-tools 같은 선택 항목도 머리말에 더 쓸 수 있습니다.

만드는 순서

다섯 단계면
첫 스킬이 완성됩니다

  1. 반복해서 하는 말을 찾습니다

    Claude에게 같은 규칙을 세 번째 설명하고 있다면 스킬로 만들 때입니다. 먼저 스킬 없이 한 번 일을 끝까지 해 보고, 그때 덧붙인 설명을 모아 둡니다.

  2. 폴더를 만들고 SKILL.md를 엽니다

    스킬 이름으로 폴더를 만들고 그 안에 SKILL.md를 새로 만듭니다. 메모장이나 VS Code 같은 아무 텍스트 편집기면 됩니다.

  3. 머리말에 이름과 설명을 씁니다

    맨 위에 ---를 쓰고 name:, description:을 적은 뒤 다시 ---로 닫습니다. 설명에는 사용자가 실제로 쓸 요청 표현을 넣습니다.

  4. 본문에 순서와 기준을 씁니다

    1단계에서 모은 규칙을 “작업 순서”, “기준”, “마지막 확인”처럼 나눠 적습니다. Claude가 이미 아는 일반 상식은 빼고, 이 일에만 필요한 내용만 남깁니다.

  5. 실제 요청으로 시험하고 다듬습니다

    새 대화에서 평소처럼 부탁해 보고, 스킬이 잘 불리는지와 결과가 기준에 맞는지 봅니다. 빠뜨린 점이 보이면 SKILL.md를 고쳐 다시 시험합니다.

    직접 쓰기 어렵다면 이렇게 부탁해도 됩니다. “방금 우리가 한 작업 방식을 SKILL.md 스킬로 만들어줘.”

Claude 앱 · 웹

ZIP으로 묶어 업로드합니다

스킬 폴더를 ZIP 파일로 압축한 뒤 설정의 Customize › Skills에서 + › Create skill › Upload a skill을 고릅니다.

Settings › Capabilities에서 “Code execution and file creation”이 켜져 있어야 합니다.

Claude Code · 나만 쓰기

내 컴퓨터 전체에서 씁니다

홈 폴더 아래에 둡니다.

~/.claude/skills/스킬이름/SKILL.md

어느 프로젝트를 열어도 이 스킬을 쓸 수 있습니다.

Claude Code · 팀과 함께

프로젝트 폴더에 둡니다

저장소 안에 둡니다.

.claude/skills/스킬이름/SKILL.md

Git에 함께 올리면 같은 저장소를 쓰는 팀원도 같은 스킬을 씁니다.

앱에서 만든 개인 스킬은 공유하거나 관리자가 배포하기 전까지 동료에게 보이지 않습니다.

어떻게 작동하나

이름표만 훑어보고,
맞는 스킬만 펼쳐 읽습니다

Claude는 처음부터 모든 스킬의 본문을 읽지 않습니다. 대화가 시작되면 각 스킬의 name과 description만 알고 있다가, 요청과 맞는 스킬을 골랐을 때 그 SKILL.md 본문을 읽고 필요한 파일을 더 엽니다.

어떻게 부르나

알아서 부르게 두거나,
이름으로 직접 부릅니다

자동 선택

평소처럼 부탁합니다

요청이 description과 잘 맞으면 Claude가 스스로 스킬을 꺼내 씁니다.

예: “MCP를 초보자용 그림 설명서로 만들어줘.”

직접 지목 · Claude Code

/스킬이름으로 부릅니다

스킬 이름은 곧 슬래시 명령이 됩니다. 뒤에 붙인 말은 본문의 $ARGUMENTS 자리에 들어갑니다.

예: /eli5-guide 스킬이란?

자동 호출 막기

내가 부를 때만 쓰게 합니다

배포처럼 함부로 실행되면 곤란한 일은 머리말에 한 줄을 더합니다.

disable-model-invocation: true

앱에서는 스킬 목록의 토글로 켜고 끕니다.

잘 쓰는 법

설명은 구체적으로,
본문은 짧고 분명하게

아쉬운 description
description: 문서 작업을 도와줍니다.

어떤 문서인지, 언제 꺼내야 하는지 알 수 없습니다. 비슷한 스킬이 많으면 선택되지 않습니다.

좋은 description
description: PDF에서 글과 표를 뽑고 양식을 채운다. PDF 파일을 다루거나 사용자가 PDF, 양식, 문서 추출을 말할 때 사용한다.

하는 일과 꺼낼 때를 모두 적었고, 사용자가 실제로 쓰는 낱말이 들어 있습니다.

잘 꺼내지게 쓰기

  • 한 스킬에는 한 가지 일만 담습니다.
  • “무엇을 한다 + 언제 쓴다”를 3인칭으로 씁니다.
  • 실제 요청 표현과 파일 형식 이름을 넣습니다.

결과가 달라지게 쓰기

  • Claude가 이미 아는 설명은 빼고 이 일만의 규칙을 씁니다.
  • “예쁘게”보다 확인할 수 있는 기준과 예시를 적습니다.
  • 마지막 확인 단계와, 틀리면 돌아갈 단계를 적습니다.
자주 하는 실수 01

파일 경로를 scripts\run.py처럼 역슬래시로 씁니다. 항상 scripts/run.py처럼 슬래시를 씁니다.

자주 하는 실수 02

참고 파일이 또 다른 파일을 가리키게 겹겹이 연결합니다. 모든 참고 파일은 SKILL.md에서 바로 연결합니다.

자주 하는 실수 03

“8월 이후에는 새 방식을 써라”처럼 날짜에 묶인 지시를 넣습니다. 지금 쓰는 방법만 적어 둡니다.

스킬이 권한까지 만들어 주지는 않습니다

스킬은 ‘어떻게 일할지’를 알려 줄 뿐입니다. 메일, 드라이브, 데이터베이스에 접근하려면 커넥터나 MCP 연결과 사용자 권한이 따로 필요합니다. 스크립트가 들어 있는 스킬은 믿을 수 있는 곳에서 받은 것만 설치하고, 설치 전에 폴더 안 파일을 먼저 살펴보세요.
